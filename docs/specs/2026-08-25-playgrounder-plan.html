playgrounder — implementation plan

Build sequence for playgrounder v0.1.0, derived from the design spec. Each step ends in a verifiable gate. Written 2026-08-25.

Principles

  • Vertical slices, each independently green. The order is chosen so that after every step, fvm flutter test and fvm flutter analyze pass — never a half-wired tree.
  • Tests land with the code they cover, not after. The package job enforces 100% line coverage, so a step that adds a widget adds its test in the same step or it fails CI.
  • Transform, don't invent. Most widgets are flowin source with three edits: drop the flutter_flowin import, replace flowin tokens with private consts, route chrome through PlaygroundStyle. Keep flowin's doc comments and the reasoning in them.
  • Every command through fvm; every commit is --amend onto the single seed commit until first release (matches lowframer history policy).

Hard gates, unchanged. No dart pub publish without separate explicit approval. No push / PR before you validate the running example and say so. File edit and git commit are separate tool calls (lefthook heredoc-parse bug). cd into the target repo in every bash call.

Step 1 — Tokens + relevance + value types (no widgets)

Deliverable: the dependency-free leaves everything else imports.
  • src/_tokens.dart — private consts: gap = 8.0, inset = 24.0, hairline = 1.0 (were space200, space600, borders.regular).
  • src/knobs/knob_relevance.dart — KnobRelevance (flowin's FlowinKnobRelevance, rename only; drop the flowin import — it uses none of it beyond @immutable, keep that via meta/foundation).
  • src/playground/playground_preset.dart — PlaygroundPreset<T> (Equatable, unchanged shape).
  • src/playground/playground_action.dart — PlaygroundAction (unchanged shape).
  • src/knobs/scale_knob.dart — add the new ScaleStep value class here (name + double, value equality). Knob widget itself comes in Step 3.
  • Tests: value equality of PlaygroundPreset, PlaygroundAction, ScaleStep; KnobRelevance.when/.always fields.

100% coverage on these files; analyze clean.

Step 2 — PlaygroundStyle + Scope (the seam, Material defaults)

Deliverable: the injection point, fully usable with stock Material.
  • src/style/playground_style.dart — PlaygroundStyle base class with the four members from the spec, each defaulting to Material: buildTabs → TabBar; buildPresetRow / buildActionButton → full-width FilledButton.tonalIcon; stageBackground → surfaceContainerHighest.
  • Same file: PlaygroundStyleScope extends InheritedWidget, with static PlaygroundStyle of(BuildContext) returning the ambient style or const PlaygroundStyle(), and updateShouldNotify.
  • Tests: of returns the default with no scope in the tree; returns the injected style when wrapped; a subclass overriding one member keeps the base defaults for the rest.

A pumped PlaygroundStyleScope resolves correctly both ways; 100% coverage.

Step 3 — Knob widgets

Deliverable: the three knobs + group, all raw-Material, all covered.
  • src/knobs/step_knob.dart — StepKnob<T> (flowin's, already generic; drop flowin import, use Theme.of/textTheme directly instead of context.textTheme sugar).
  • src/knobs/switch_knob.dart — SwitchKnob (from FlowinPlaygroundSwitchKnob; FlowinDesignSpace.space200 → gap).
  • src/knobs/knob_group.dart — KnobGroup (from FlowinPlaygroundKnobGroup; caps heading, relevance-hide).
  • src/knobs/scale_knob.dart — ScaleKnob = thin wrapper over StepKnob<ScaleStep> with baked 'name — Npx' labelOf. (Replaces flowin's spacing knob; no theme resolution inside — the consumer passes resolved steps.)
  • Tests: step-knob slider maps index↔value and snaps (divisions == values.length - 1); switch toggles; group + knob hide to SizedBox.shrink when irrelevant; scale-knob readout string.

Every knob renders and drives its callback; irrelevant paths covered; 100%.

Step 4 — Private inspector internals

Deliverable: preview stage, preset list, actions region, inspector — all private, all routing chrome through the style.
  • src/playground/preview/playground_preview.dart — the stage. Background = style.stageBackground(context) unless a per-call background is passed. (flowin's outlineVariant literal is gone; it becomes flowin's override later.)
  • src/playground/inspector/playground_presets.dart — preset list. Each row = style.buildPresetRow(...) instead of FlowinItemButton.tonal. The active-check + "Custom" caption stay.
  • src/playground/inspector/playground_actions.dart — pinned region. Each action = style.buildActionButton(...); the divider uses hairline.
  • src/playground/inspector/playground_inspector.dart — docked region. Tab row = style.buildTabs(...). Keep the initState-not-late-final TabController fix. Panels swapped (not TabBarView), presetless path падding-only.
  • Tests: preview honors per-call background over style; presets render N rows + drift-to-Custom caption; actions pin and fire; inspector's presetless branch builds without a dispose-time ticker crash (the regression flowin never wrote).

Inspector + subparts covered including the empty-presets branch; analyze clean; 100%.

Step 5 — Playground (the public composition) + barrel

Deliverable: Playground<T> wiring it together; the package's public API is complete.
  • src/playground/playground.dart — Playground<T>: LayoutBuilder split at 900px (stacked ListView + Divider below, docked 300px Row above), _activePreset by ==, delegates preview/inspector building. Reads PlaygroundStyle.of(context).
  • lib/playgrounder.dart — export all 13 public symbols.
  • Tests: breakpoint stack-vs-dock (pump at 800 and 1000 wide, assert layout); active-preset resolves and drifts to Custom on knob change; default-style vs injected-style buttons appear; end-to-end config round-trip through a knob.

Full public surface exercised; 100% line coverage on lib/; analyze clean. Amend seed commit.

Step 6 — playgrounder's own example (single Material playground)

Deliverable: example/ — one bare playground on the zero-config Material path.
  • example/ as a separate package (own pubspec.yaml with a path dep on playgrounder and nothing else, own analysis_options.yaml), mirroring lowframer's example setup. No flutter_flowin dependency.
  • example/lib/main.dart — a single Playground filling the screen, no scope, no app shell or tabs. Framing chrome (tabs, nav) belongs to a consumer's app, not to the playground affordance, so the example is nothing but the preview and inspector.
  • Subject: a small card config exercising two switch knobs + a scale knob under a KnobGroup, two presets, one "copy config" action.
  • The PlaygroundStyle injection path is documented in the README and proven live by the lowframer example (Step 7); it is not shown in playgrounder's own example.

Example is analyze-only in CI (no example tests, matching lowframer). Locally: run it, visually confirm the single playground. Stop here and hand a screenshot to the user for review.

Step 7 — Wire the lowframer example against playgrounder (path dep)

Deliverable: the actual motivation — a live preview + knobs inside the lowframer example.
  • In ~/Work/Projects/lowframer/example/pubspec.yaml, add a path dep on ../../playgrounder.
  • Add a playground page to the lowframer example that previews one of its arts (e.g. the Buttons or Dashboard art) with a couple of knobs, using the default Material style (no scope). This is the zero-config proof.
  • This touches the lowframer repo — a separate change on its own branch there, committed locally, not pushed, reported as such.

lowframer example runs with the embedded playground; user validates visually. Both repos' changes committed locally, nothing pushed.

Effort shape

Seven steps, ~18 source files, most transformed from ~584 LOC of existing flowin playground code rather than written cold. The genuinely new code is small: PlaygroundStyle + Scope, ScaleStep/ScaleKnob, and the presetless-inspector regression test. The rest is mechanical rename + de-flowin + route-through-style, preserving flowin's doc comments and reasoning.
